# ADR-0005: The operational-rules section number is a persisted on-disk schema number

- Status: accepted
- Date: 2026-08-04

## Context

`/proxyme-identity` writes a section numbered 7 (`## 7. Proxy operational
rules`) into every identity file it generates, and its staleness guard scopes
the identity side of a `comm` with `sed -n '/^## 7\./,$p'`. The guard runs
against identity files already on users' disks, including files generated by
older versions of the skill — that is stated scope for the skill, not an edge
case.

That makes the number a schema number, not a source-internal constant. A release
that inserts a section and renumbers operational rules to 8 can be perfectly
self-consistent across the template, the guard anchor and the fixture, and still
break every existing user: the guard scopes for `## 8.`, a user's file has
`## 7.`, the extraction is empty, and the guard reports "nothing stale" forever.
The failure is silent — the guard keeps running and keeps saying everything is
current.

Until now this was recorded only as a comment inside
`proxyme/lib/proxyme-paths.test.sh`, discoverable to a contributor only as a
failing assertion.

## Decision

The number is frozen at 7. Renumbering requires migration support in the shipped
guard FIRST — a guard that reads both generations — and only then a renumber.

`proxyme/lib/proxyme-paths.test.sh` makes drift a build failure, checking the
template heading, the guard's `sed` anchor, the fixture's section shape, and
prose references across an explicit, listed set of shipped files.
`proxyme/AGENTS.md` documents the freeze, the covered set and the migration
precondition where a contributor editing shipped prose will meet it.

## Consequences

- Renumbering is a two-release change, never a one-commit rename.
- Adding shipped prose that names the section means adding that file to
  `SECTION_REF_FILES` in the test; an unlisted file is not covered.
- Prose about other sections of the template is unconstrained — the check
  requires the frozen number to be present per file, it does not forbid other
  numbers.
- The fixture is held to one numbered section, the frozen one. A section
  numbered above it would be swept into the guard's `,$p` scope, so growing one
  is a build failure until the expectation is widened deliberately.

## Alternatives

- **Anchor on heading text instead of the number.** Rejected: the template
  renders in the user's own language, so a real identity's heading reads e.g.
  `## 7. Regras operacionais do proxy`. Only the number survives translation.
- **Leave the freeze as a test comment.** Rejected: it binds the product, and a
  contributor met it only as a failing assertion whose name mentions the number
  and nothing else.
